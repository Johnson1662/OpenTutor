# OpenLearner 前端旗舰级 Polish 设计

日期：2026-03-25  
范围：首页、课程列表、课程详情、学习流程、AI 助手、上传与反馈弹层、全局主题与交互细节  
质量目标：旗舰级

## 背景

当前前端功能已经基本可用，但仍存在明显的未收口问题：

- 视觉风格混杂，浅色极简 token、紫色渐变、硬编码状态色并存
- 中文产品里混有较多英文文案，完成度感不足
- 多个交互缺少完整状态与无障碍补齐
- 移动端存在固定宽高弹层、拥挤网格和偏小触控目标
- 动画较多但未做 reduced motion 收口

本次 polish 不改变核心业务流程，不新增复杂功能，以“统一体验、提升精致度、补齐关键可用性细节”为目标。

## 设计目标

1. 让界面更符合 OpenLearner 既有设计方向：温暖、清晰、邀请式
2. 从视觉上去掉 AI 拼接感，减少模板化卡片、硬编码色和语言混杂
3. 提升交互完整度：hover、focus、active、disabled、loading、error、success 都有一致表达
4. 优先补齐最影响真实使用体验的无障碍与移动端细节
5. 在不重构架构的前提下，让关键路径看起来更像可交付产品而不是原型

## 方案对比

### 方案 A：轻量收口

- 只改文案、颜色、少量间距和按钮状态
- 风险最低，速度最快
- 缺点是结构性的视觉问题和移动端问题会继续保留

### 方案 B：推荐，整体收口

- 统一主题 token 的实际使用
- 修复首页、课程、学习流、弹层、助手这些高可见区域
- 一并处理关键无障碍和响应式问题
- 不大改信息架构，但显著提升整体完成度

### 方案 C：深度重构

- 重写多个页面布局，拆分组件系统，重做大部分动效与版式
- 视觉提升最大，但改动范围与回归风险过高，不适合当前阶段

结论：采用 **方案 B**。

## 视觉方向

- 基调保持浅色、柔和、学习陪伴感
- 以绿 / 蓝 / 金作为功能强调，而不是紫色演示风格
- 中性色轻微带暖，避免纯黑纯灰造成产品过冷
- 保留适度边框和层级，但减少无意义的卡片堆叠与玻璃态

## 体验策略

### 1. 主题与颜色

- 把高频状态色统一回 token 系统
- 清除 `PDFUploader`、反馈面板、旧课程容器等组件中的紫色渐变和散落硬编码色
- 让成功 / 警告 / 错误语义在所有页面保持一致

### 2. 文案统一

- 中文优先，保留必要英文专有名词但不再混入普通按钮和状态文案
- 收口按钮名称、空状态、课程标签、反馈标题、输入占位语
- 去掉重复表达，让文案更短、更自然

### 3. 交互状态

- 为主要按钮和可点击表面补齐 focus-visible、disabled、loading、active
- 清理“看起来可点击但不能点”的表面
- icon-only 按钮补齐可访问名称

### 4. 响应式与触控

- 调整固定宽高弹层，使其在窄屏下改为更稳的边距布局
- 降低首页和课程区在手机上的拥挤感
- 提升关键触控区域到更接近 44x44

### 5. 动效与细节

- 动效只保留有状态意义的部分
- 对持续动画、进度动画和弹层过渡增加 reduced-motion 降级
- 避免继续使用直接 height 动画的地方，优先收敛到更轻量的过渡方式

## 具体落点

### 首页与导航

- 调整 `HomeView` 的文案、快捷区、空状态和课程网格密度
- 调整 `Navbar` 的按钮尺寸、焦点态和移动端菜单过渡

### 课程列表与详情

- 修复 `CourseView` 中假按钮和死控件
- 收口标题、副标题、进度信息、删除操作样式
- 优化课程卡片在移动端和桌面端的统一性

### 学习流程

- 优化 `LevelView` 的按钮状态、文案与辅助反馈
- 让反馈面板、步骤标签和 XP 表达更统一
- 对 `Segmenter`、`ChoiceCard` 等交互控件补齐键盘/焦点表达

### 弹层与助手

- 收口 `FeedbackModal`、`UserFeedbackModal`、`AIAssistant`、`CourseCreator` 的视觉与文案
- 统一弹层结构、关闭按钮、标题层级和窄屏表现

## 无障碍与健壮性边界

本次 polish 会优先修复高价值问题：

- dialog 语义
- icon-only 按钮标签
- progressbar 语义
- focus-visible
- reduced-motion

但不会在本轮做完整的无障碍专项治理，例如复杂键盘拖拽交互的全量无障碍重构。

## 风险控制

- 不改后端接口与数据结构
- 不重写页面架构，只在现有组件上收口
- 对审计中已确认的问题优先处理，避免为了“更好看”引入新行为风险

## 验证计划

- `npm run lint`
- `npm run build`
- `python start.py`
- 手动检查首页、课程页、学习流程、弹层、移动端窄宽度布局

## 预期结果

完成后，OpenLearner 前端应达到以下状态：

- 视觉语言统一，不再有明显 AI 风格拼贴感
- 中文体验收口，交互文案更自然
- 主要交互具备完整状态和基础无障碍语义
- 移动端不再有明显拥挤、溢出和小触控点问题
- 动效更克制，页面更像准备上线的正式产品
